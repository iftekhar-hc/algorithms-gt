== Philosophy & Design Goals

Both {cpp} and {rust} occupy the same niche: systems languages with zero-cost abstractions and no garbage collector.
But they make different bets about where to put complexity.

[cols="1,2,2", options="header"]
|===
| Concern | {cpp} Approach | {rust} Approach

| Memory safety
| Programmer discipline + tools (ASan, Valgrind)
| Compile-time borrow checker

| Undefined behaviour
| Vast UB surface; optimiser exploits it
| Eliminated in safe code; opt-in via `unsafe`

| Null pointers
| Raw pointers, optional references
| `Option<T>` — null is not a value

| Error handling
| Exceptions or error codes (mixed)
| `Result<T, E>` — errors are values

| Concurrency
| Mutexes, atomic ops, programmer-verified
| `Send`/`Sync` traits enforced at compile time

| Abstraction cost
| Zero-cost (mostly)
| Zero-cost (guaranteed by design)

| Build system
| CMake / Meson / Bazel / make
| Cargo (first-party, universal)

| Package management
| Conan, vcpkg (fragmented)
| crates.io (first-party)
|===

[NOTE]
====
Rust moves the complexity from runtime debugging into the type system.
Code that compiles is _far_ more likely to be correct.
The borrow checker is not a limitation — it's the compiler doing the work your code review was doing.
====

== Syntax Crash Course

=== Variables & Mutability

In {cpp}, variables are mutable by default; `const` opts out.
Rust flips this: *immutable by default*, `mut` opts in.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
int x = 42;          // mutable
const int y = 10;    // immutable
x = 99;              // ok

auto z = 3.14;       // type inferred
----

|
[source,rust]
----
let x = 42;           // immutable
let mut y = 10;       // mutable
y = 99;               // ok

let z: f64 = 3.14;   // explicit type
let w = 3.14_f64;    // suffix inferred
----

|===

=== Functions

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
int add(int a, int b) {
    return a + b;
}

// trailing return
auto mul(int a, int b) -> int {
    return a * b;
}
----

|
[source,rust]
----
fn add(a: i32, b: i32) -> i32 {
    a + b  // no semicolon = return value
}

// explicit return also works
fn mul(a: i32, b: i32) -> i32 {
    return a * b;
}
----

|===

[TIP]
====
Rust is expression-based.
A block `{ ... }` evaluates to its last expression if it lacks a trailing semicolon.
This applies to `if`, `match`, loops, and function bodies.
====

=== Control Flow

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// switch
switch (status) {
  case 0: handle_ok();  break;
  case 1: handle_err(); break;
  default: break;
}

// range-for
for (auto& item : vec) {
    process(item);
}
----

|
[source,rust]
----
// match (exhaustive!)
match status {
    0 => handle_ok(),
    1 => handle_err(),
    _ => {}  // wildcard required
}

// for-in with iterators
for item in &vec {
    process(item);
}
----

|===

=== Closures

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// capture by value/ref
auto add = [=](int x) {
    return x + base;
};

// std::function (type-erased)
std::function<int(int)> f = add;
----

|
[source,rust]
----
// capture inferred
let add = |x| x + base;

// trait objects (type-erased)
let f: Box<dyn Fn(i32) -> i32>
    = Box::new(add);

// or impl Fn (static dispatch)
fn apply(f: impl Fn(i32) -> i32) { }
----

|===

== Type System

=== Primitive Types

[cols="1,1,2", options="header"]
|===
| {cpp} Type | {rust} Equivalent | Notes

| `int`         | `i32`    | Rust requires explicit width always
| `unsigned int`| `u32`    |
| `int64_t`     | `i64`    |
| `size_t`      | `usize`  | Pointer-sized, used for indexing
| `float`       | `f32`    |
| `double`      | `f64`    | Rust default float literal type
| `bool`        | `bool`   | Same
| `char`        | `char`   | Rust `char` is always Unicode scalar (4 bytes)
| `void`        | `()`     | Unit is a real zero-sized type, not absence
| `T*`          | `*const T` / `*mut T` | Raw pointers exist but require `unsafe`
| `T&`          | `&T` / `&mut T`       | Always valid (lifetime-checked)
|===

=== Strings

{cpp} has `std::string` (heap, owned) and `std::string_view` (borrowed).
Rust mirrors this cleanly:

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
std::string owned = "hello";
std::string_view view = owned;

const char* raw = "literal";
owned += " world";
----

|
[source,rust]
----
let owned: String = String::from("hello");
let view: &str = &owned;    // borrowed slice
let literal: &str = "world"; // static lifetime

let mut s = owned;
s.push_str(" world");
----

|===

=== Collections

[cols="1,1", options="header"]
|===
| {cpp} Container | {rust} Equivalent

| `std::vector<T>`           | `Vec<T>`
| `std::array<T,N>`          | `[T; N]`
| `std::span<T>`             | `&[T]` / `&mut [T]`
| `std::unordered_map<K,V>`  | `HashMap<K,V>`
| `std::map<K,V>`            | `BTreeMap<K,V>`
| `std::optional<T>`         | `Option<T>`
| `std::variant<A,B>`        | `enum Foo { A(...), B(...) }`
| `std::tuple<A,B>`          | `(A, B)` tuple
|===

== Ownership

The single most important concept in Rust — and its biggest departure from {cpp}.

Every value in Rust has exactly one *owner*.
When the owner goes out of scope, the value is dropped (destructor called, memory freed).
No GC, no manual `delete`.

=== The Three Rules

[IMPORTANT]
====
. Every value has exactly one owner.
. When the owner goes out of scope, the value is dropped.
. Ownership can be *moved* or *cloned*, never silently copied (for heap types).
====

=== Move Semantics — Default, Not Optional

{cpp} added move semantics in C++11, but copy is still the default for types that implement it.
In Rust, *move is always the default* for non-`Copy` types.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
std::vector<int> v = {1,2,3};
std::vector<int> w = v;  // COPY
// v still valid

std::vector<int> x = std::move(v);
// v is now in moved-from state
// using v is UB if not re-assigned
----

|
[source,rust]
----
let v: Vec<i32> = vec![1,2,3];
let w = v;        // MOVE (ownership transferred)
// v is now invalid — compiler error if used

let x = w.clone(); // explicit deep copy
// w and x both valid
----

|===

=== Copy Types

Primitive types (`i32`, `f64`, `bool`, `char`) and types composed of them implement the `Copy` trait.
Copying is implicit and cheap — exactly like {cpp} for `int`, `double`, etc.

[source,rust]
----
let x: i32 = 5;
let y = x;  // copy, not move — x still valid
println!("{x} {y}");  // both work

// Your struct can opt into Copy:
#[derive(Copy, Clone)]
struct Point { x: f32, y: f32 }
----

=== RAII — Exactly What You Know

Rust's drop semantics are identical to {cpp} RAII.
The `Drop` trait is `std::~Destructor`.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
struct File {
    FILE* f;
    ~File() { fclose(f); }
};

{
    File guard{fopen("x","r")};
} // destructor called here
----

|
[source,rust]
----
struct File { ptr: *mut libc::FILE }

impl Drop for File {
    fn drop(&mut self) {
        unsafe { fclose(self.ptr); }
    }
}
{
    let _guard = File { ptr: ... };
} // drop() called here
----

|===

== Borrowing & References

How Rust eliminates use-after-free, dangling pointers, and data races at compile time.

Rust's references are like {cpp} references — always valid, never null — but with strict aliasing rules enforced by the compiler.

[WARNING]
====
*The Aliasing XOR Mutability Rule*

At any point in time, you may have *either*:

* Any number of shared references `&T` (read-only), *or*
* Exactly one mutable reference `&mut T` (read-write)

But never both simultaneously. This is enforced at compile time.
====

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
std::vector<int> v = {1,2,3};
const int& r1 = v[0];
const int& r2 = v[0];
v.push_back(4);  // UB! r1,r2 dangling
std::cout << r1; // undefined behaviour
----

|
[source,rust]
----
let mut v = vec![1,2,3];
let r1 = &v[0];
let r2 = &v[0];
v.push(4);  // ❌ compile error!
            // cannot borrow `v` mutably
            // while immutably borrowed
println!("{r1}");
----

|===

=== Shared vs Mutable References

[source,rust]
----
fn print_len(s: &String) {           // shared borrow
    println!("{}", s.len());
}

fn append(s: &mut String) {          // mutable borrow
    s.push_str(" world");
}

let mut hello = String::from("hello");
print_len(&hello);                   // lends immutably
append(&mut hello);                  // lends mutably
print_len(&hello);                   // ok again
----

=== Slices — Rust's `std::span`

A slice `&[T]` is a fat pointer (pointer + length) — the equivalent of `std::span<T>` but lifetime-checked.

[source,rust]
----
fn sum(nums: &[i32]) -> i32 {   // works on Vec, array, or any contiguous memory
    nums.iter().sum()
}

let v = vec![1, 2, 3, 4];
sum(&v);          // whole Vec
sum(&v[1..3]);    // sub-slice [2, 3]
sum(&[10, 20]);   // array literal coerced
----

== Lifetimes

Making the implicit explicit — and verifiable.

Lifetimes are Rust's way of expressing "this reference must not outlive the data it points to."
In {cpp}, this is checked at runtime (or not at all).
In Rust, it's a compile-time annotation that the borrow checker verifies.

[NOTE]
====
The compiler infers lifetimes in simple cases (lifetime elision).
You only write explicit lifetime annotations `'a` when the compiler can't determine which input borrow ties to the output borrow.
====

=== Lifetime Elision vs Explicit Annotations

[source,rust]
----
// Compiler infers: output lives as long as input
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();
    for (i, &b) in bytes.iter().enumerate() {
        if b == b' ' { return &s[..i]; }
    }
    s
}

// Must annotate: compiler can't decide which input owns output
fn longer<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
// 'a means: output lives as long as the shorter of x or y

// Struct holding a reference needs a lifetime
struct Excerpt<'a> {
    text: &'a str,
}
----

=== Static Lifetime

[source,rust]
----
// String literals live for the entire program
let s: &'static str = "I live forever";

// Be wary of using 'static to "fix" lifetime errors —
// it usually signals a design issue.
----

== Smart Pointers

[cols="1,1,2", options="header"]
|===
| {cpp} Type | {rust} Type | Notes

| `std::unique_ptr<T>`        | `Box<T>`      | Single owner, heap allocated
| `std::shared_ptr<T>`        | `Rc<T>`       | Ref-counted, single-threaded
| `std::shared_ptr<T>`        | `Arc<T>`      | Atomically ref-counted, thread-safe
| `std::weak_ptr<T>`          | `Weak<T>`     | Non-owning ref to `Rc`/`Arc`
| `std::mutex<T>` (conceptual)| `Mutex<T>`    | Data _inside_ the mutex, not separate
| `mutable T` (interior mut.) | `Cell<T>` / `RefCell<T>` | Allows mutation through shared ref
|===

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// unique ownership
auto p = std::make_unique<Widget>(42);
use(*p);

// shared ownership
auto s = std::make_shared<Widget>(1);
auto t = s;   // refcount++
----

|
[source,rust]
----
// unique ownership (heap)
let p = Box::new(Widget::new(42));
use_it(&p);

// shared ownership
let s = Rc::new(Widget::new(1));
let t = Rc::clone(&s);  // refcount++
----

|===

=== Interior Mutability — Rust's Answer to `mutable`

Sometimes you need mutability behind a shared reference (e.g., caches, event handlers).
{cpp} uses `mutable` members; Rust uses `RefCell<T>` (runtime borrow checking) or `Cell<T>` (copy types).

[source,rust]
----
use std::cell::RefCell;

let data = RefCell::new(vec![1, 2, 3]);

// Borrow rules checked at runtime, not compile time
data.borrow().iter().for_each(|x| println!("{x}"));
data.borrow_mut().push(4);   // panics if already borrowed
----

== Structs & Enums

=== Structs (No Classes)

Rust has no classes.
Structs hold data; `impl` blocks provide methods.
Inheritance doesn't exist — composition and traits replace it.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
class Rectangle {
public:
    double width, height;
    Rectangle(double w, double h)
        : width(w), height(h) {}
    double area() const {
        return width * height;
    }
};
----

|
[source,rust]
----
struct Rectangle {
    width: f64,
    height: f64,
}

impl Rectangle {
    fn new(w: f64, h: f64) -> Self {
        Self { width: w, height: h }
    }
    fn area(&self) -> f64 {
        self.width * self.height
    }
}
----

|===

=== Enums — Algebraic Data Types

Rust's `enum` is vastly more powerful than C/{cpp} enums.
Each variant can carry data of different types — equivalent to a tagged union, but safe.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// C++17 std::variant
using Shape = std::variant<
    Circle, Rectangle, Triangle
>;

auto area = std::visit(overloaded{
    [](Circle c)    { return M_PI*c.r*c.r; },
    [](Rectangle r) { return r.w * r.h; },
    [](Triangle t)  { return 0.5*t.b*t.h; },
}, shape);
----

|
[source,rust]
----
enum Shape {
    Circle { radius: f64 },
    Rect   { w: f64, h: f64 },
    Tri    { base: f64, height: f64 },
}

let area = match shape {
    Shape::Circle { radius: r } =>
        std::f64::consts::PI * r * r,
    Shape::Rect { w, h } => w * h,
    Shape::Tri { base: b, height: h } =>
        0.5 * b * h,
};
----

|===

[TIP]
====
The compiler will refuse to compile a `match` that doesn't cover all variants.
Adding a new enum variant will produce compile errors everywhere it's matched — exactly what you want.
====

=== Option and Result — Enums in Disguise

[source,rust]
----
// Option replaces nullable pointers
let maybe: Option<i32> = Some(42);
let none:  Option<i32> = None;

// pattern match
match maybe {
    Some(v) => println!("got {v}"),
    None    => println!("nothing"),
}

// or use combinators
let doubled  = maybe.map(|v| v * 2);
let fallback = none.unwrap_or(0);

// Result: Ok(value) or Err(error)
fn parse(s: &str) -> Result<i32, String> {
    s.parse().map_err(|e| e.to_string())
}

let n = parse("42")?;  // ? propagates error to caller
----

'''

== Traits vs Concepts

Traits are Rust's answer to {cpp} abstract base classes _and_ C++20 Concepts.
They define shared behaviour without inheritance.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// Abstract base class
class Drawable {
public:
    virtual void draw() const = 0;
    virtual ~Drawable() = default;
};

// C++20 Concept
template<typename T>
concept Drawable = requires(T t) {
    { t.draw() } -> std::same_as<void>;
};
----

|
[source,rust]
----
// Trait definition
trait Drawable {
    fn draw(&self);
    // default implementations allowed:
    fn draw_twice(&self) {
        self.draw(); self.draw();
    }
}

// Implement for a type
impl Drawable for Circle {
    fn draw(&self) {
        println!("○ r={}", self.radius);
    }
}
----

|===

=== Static vs Dynamic Dispatch

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// Static (template)
template<Drawable T>
void render(T& d) { d.draw(); }

// Dynamic (virtual)
void render(Drawable* d) { d->draw(); }
std::vector<Drawable*> scene;
----

|
[source,rust]
----
// Static dispatch (monomorphised)
fn render(d: impl Drawable) { d.draw(); }

// Dynamic dispatch (vtable, like virtual)
fn render(d: &dyn Drawable) { d.draw(); }
let scene: Vec<Box<dyn Drawable>> = vec![];
----

|===

=== Operator Overloading via Traits

[source,rust]
----
use std::ops::Add;

#[derive(Debug, Clone, Copy)]
struct Vec2 { x: f32, y: f32 }

impl Add for Vec2 {
    type Output = Vec2;
    fn add(self, other: Vec2) -> Vec2 {
        Vec2 { x: self.x + other.x, y: self.y + other.y }
    }
}

let a = Vec2 { x: 1.0, y: 2.0 };
let b = Vec2 { x: 3.0, y: 4.0 };
let c = a + b;  // Vec2 { x: 4.0, y: 6.0 }
----

== Generics & Templates

Rust generics compile to the same efficient code as {cpp} templates (monomorphization).
But they're checked at the point of definition, not instantiation.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
template<typename T>
T largest(const std::vector<T>& v) {
    T max = v[0];
    for (const T& x : v)
        if (x > max) max = x;
    return max;
}
// Error only at instantiation
----

|
[source,rust]
----
fn largest<T: PartialOrd>(v: &[T]) -> &T {
    let mut max = &v[0];
    for x in v {
        if x > max { max = x; }
    }
    max
}
// Error at definition if T lacks PartialOrd
----

|===

=== Where Clauses for Complex Bounds

[source,rust]
----
// Long form with where (equivalent to inline bounds)
fn serialize_and_print<T>(item: &T)
where
    T: serde::Serialize + std::fmt::Debug + Send,
{
    println!("{item:?}");
    let json = serde_json::to_string(item).unwrap();
    println!("{json}");
}
----

== Error Handling

Rust has no exceptions.
Errors are either recoverable (`Result<T, E>`) or unrecoverable (`panic!`).
This makes error paths explicit in every function signature.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// Throws — caller may not know
std::string read_file(const std::string& p) {
    std::ifstream f(p);
    if (!f) throw std::runtime_error("open failed");
    return {std::istreambuf_iterator<char>(f), {}};
}
----

|
[source,rust]
----
// Caller must handle Result
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}

// ? operator propagates errors
fn process() -> Result<(), Box<dyn std::error::Error>> {
    let content = read_file("data.txt")?;
    let n: i32 = content.trim().parse()?;
    println!("parsed: {n}");
    Ok(())
}
----

|===

=== Custom Error Types

[source,rust]
----
use thiserror::Error;  // thiserror crate

#[derive(Debug, Error)]
enum AppError {
    #[error("I/O failed: {0}")]
    Io(#[from] std::io::Error),

    #[error("parse error: {msg}")]
    Parse { msg: String },
}

fn load() -> Result<i32, AppError> {
    let s = std::fs::read_to_string("n.txt")?; // auto-converts io::Error
    s.trim().parse().map_err(|_| AppError::Parse {
        msg: format!("not a number: {s}")
    })
}
----

== Threads & Sync

Fearless concurrency — data races are compile-time errors.

The `Send` and `Sync` traits form Rust's concurrency safety model.
They're automatically derived and restrict what can cross thread boundaries.

[cols="1,2,2", options="header"]
|===
| Marker trait | Meaning | Example types

| `Send`
| Safe to send ownership to another thread
| Most types; not `Rc<T>`, raw pointers

| `Sync`
| Safe to share reference across threads
| Most types; not `Cell<T>`, `RefCell<T>`
|===

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
std::mutex mtx;
int shared = 0;

auto t = std::thread([&] {
    std::lock_guard lock(mtx);
    shared += 1;
});
t.join();
// Forgetting lock = data race, silent UB
----

|
[source,rust]
----
use std::sync::{Arc, Mutex};

let shared = Arc::new(Mutex::new(0));
let s = Arc::clone(&shared);

let t = std::thread::spawn(move || {
    *s.lock().unwrap() += 1;
});
t.join().unwrap();
// Can't access data without locking — enforced!
----

|===

[WARNING]
====
Rust prevents data races but not deadlocks.
Logic errors (lock ordering, etc.) remain your responsibility — just as in {cpp}.
====

=== Channels — CSP Style

[source,rust]
----
use std::sync::mpsc;

let (tx, rx) = mpsc::channel();

std::thread::spawn(move || {
    tx.send(42).unwrap();
});

let val = rx.recv().unwrap();
println!("received {val}");
----

== Async / Await

Stackless coroutines — no runtime included.

Rust's async is similar to C++20 coroutines — zero-cost, stackless, compiled to state machines.
Unlike {cpp}, `async`/`await` is idiomatic and widely used via runtimes like Tokio.

[cols="1a,1a", options="header"]
|===
| {cpp} | {rust}

|
[source,cpp]
----
// C++20 coroutine
std::future<std::string>
fetch(std::string url) {
    auto resp = co_await http_get(url);
    co_return resp.body();
}
----

|
[source,rust]
----
// Rust async fn (returns impl Future)
async fn fetch(url: &str) -> String {
    let resp = reqwest::get(url)
        .await
        .unwrap();
    resp.text().await.unwrap()
}

// Needs a runtime to execute
#[tokio::main]
async fn main() {
    let body = fetch("https://example.com").await;
}
----

|===

[NOTE]
====
`async fn` returns a `Future` — a lazy value that does nothing until driven by an executor.
You must choose a runtime: *Tokio* (most popular), *async-std*, or *smol*.
This is unlike Go or Node.js where the runtime is baked in.
====

'''

== Cargo vs CMake

First-party tooling changes everything.

[cols="1,2,2", options="header"]
|===
| Task | {cpp} | {rust}

| Build               | `cmake --build .`                     | `cargo build`
| Release build       | `cmake -DCMAKE_BUILD_TYPE=Release`    | `cargo build --release`
| Run                 | `./build/app`                         | `cargo run`
| Test                | GoogleTest / Catch2 (manual setup)    | `cargo test` (built in)
| Benchmark           | Google Benchmark (separate)           | `cargo bench`
| Docs                | Doxygen (separate)                    | `cargo doc` (built in)
| Add dependency      | vcpkg/Conan + CMakeLists.txt          | `cargo add serde`
| Lint                | clang-tidy (separate)                 | `cargo clippy` (built in)
| Format              | clang-format (separate)               | `cargo fmt` (built in)
|===

== Unsafe Rust

The escape hatch — not a license, a contract.

`unsafe` blocks tell the compiler "I take responsibility for these invariants."
The surface area of UB in Rust is much smaller than in {cpp}, and explicitly delineated.

=== What unsafe Allows

[WARNING]
====
. Dereference raw pointers (`*const T`, `*mut T`)
. Call `unsafe` functions (including FFI)
. Access or modify mutable static variables
. Implement `unsafe` traits (`Send`, `Sync`)
. Access fields of `union` types
====

[source,rust]
----
let mut v = vec![1, 2, 3];
let raw: *mut i32 = v.as_mut_ptr();

unsafe {
    // Programmer guarantees: ptr valid, aligned, in bounds
    *raw.add(1) = 99;
}

assert_eq!(v, [1, 99, 3]);

// Split a slice into two non-overlapping mutable halves
// Safe functions can't express this — unsafe enables it
let (left, right) = v.split_at_mut(2);
----

[TIP]
====
Wrap unsafe code in a safe abstraction.
The unsafe block is a hot-spot that reviewers focus on.
All of Rust's standard collections are built this way — safe API, minimal unsafe interior.
====

== FFI & Interop

=== Calling C from Rust

[source,rust]
----
extern "C" {
    fn strlen(s: *const std::os::raw::c_char) -> usize;
    fn malloc(size: usize) -> *mut std::os::raw::c_void;
}

let n = unsafe {
    strlen(c"hello".as_ptr())  // c"..." = CStr literal (Rust 1.77+)
};
----

=== Exposing Rust to C/{cpp}

[source,rust]
----
#[no_mangle]
pub extern "C" fn rust_add(a: i32, b: i32) -> i32 {
    a + b
}
// Callable from C++: extern "C" int rust_add(int, int);
----

[NOTE]
====
For serious {cpp} interop, use the *cxx* crate (safe, idiomatic C++/Rust bridge) or *bindgen* (auto-generates Rust FFI from C headers).
These handle the boilerplate and type mapping.
====

=== Builder Pattern

[source,rust]
----
#[derive(Default)]
struct ServerBuilder {
    host:    Option<String>,
    port:    Option<u16>,
    threads: usize,
}

impl ServerBuilder {
    fn host(mut self, h: impl Into<String>) -> Self {
        self.host = Some(h.into()); self
    }
    fn port(mut self, p: u16) -> Self {
        self.port = Some(p); self
    }
    fn build(self) -> Result<Server, String> {
        Ok(Server {
            host: self.host.ok_or("host required")?,
            port: self.port.unwrap_or(8080),
        })
    }
}

let server = ServerBuilder::default()
    .host("localhost")
    .port(3000)
    .build()?;
----

=== Type State Pattern — Compile-time State Machines

[source,rust]
----
struct Connection<S> { state: S }
struct Disconnected;
struct Connected;

impl Connection<Disconnected> {
    fn connect(self) -> Connection<Connected> {
        Connection { state: Connected }
    }
}

impl Connection<Connected> {
    fn send(&self, data: &[u8]) { /* ... */ }
    fn disconnect(self) -> Connection<Disconnected> {
        Connection { state: Disconnected }
    }
}

let conn = Connection { state: Disconnected };
// conn.send(&[]);  // ❌ compile error — not connected yet
let conn = conn.connect();
conn.send(&[1,2,3]);  // ✓
----

=== Common Pitfalls from {cpp}

[cols="1,2", options="header"]
|===
| {cpp} Habit | {rust} Reality

| Return `T*`, caller frees
| Return `Box<T>` or `Rc<T>`; ownership is explicit

| Pass by value, rely on copy
| Only `Copy` types copy; others move. Use `.clone()` explicitly

| `this` is a raw pointer
| `self` is a proper reference; `&self` or `&mut self`

| Mutate while iterating
| Borrow checker prevents it — restructure to iterate then modify

| Global mutable state
| Requires `Mutex<T>` or `OnceLock` — intentionally friction

| Implicit integer conversion
| All casts explicit: `x as u32`, `T::try_from(x)?`

| `std::thread_local`
| `thread_local!` macro — same concept

| Uninitialized variables
| Compile error — must initialize before use
|===
